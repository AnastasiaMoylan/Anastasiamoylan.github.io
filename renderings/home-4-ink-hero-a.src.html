Process

Design flows, not screens

Most product failures don’t happen on a screen. They happen between screens: at a handoff, a failed retrieval, a permission gap, a status nobody updated. Screens come last, after the flow proves it can survive contact with reality.

Read the eight principles
  1. 1

    Map the whole journey

    Every role, every state, and every path that breaks.

    Principle 01

  2. 2

    Draw the system

    Data, roles, governance, adjacent products: one picture everyone can argue with.

    Principle 03

  3. 3

    Prototype in code

    Real data lengths, real loading time, real state transitions.

    Principle 02

  4. 4

    Let evidence decide

    Tested with the actual user group, not a convenient proxy.

    Done when what ships matches what was designed.
